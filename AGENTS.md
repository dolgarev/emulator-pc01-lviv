# AGENTS.md - Emulator PC-01 Lviv

## Project Overview

**Emulator PC-01 Lviv** is an emulator of the Soviet home computer PC-01 "Lviv" (Ukraine, 1980s), written in JavaScript and HTML5. The project has been migrated from a deprecated Chrome Packaged App (manifest v2) to a modern Vite-based Single Page Application (SPA).

**Current Status**: Phase 1 of migration complete - SPA works in any modern browser. Phase 2 (PWA) and Phase 3 (code quality) are pending.

## Architecture

```
Emulator (entry point in main.js)
 └── Computer
      └── Profile (orchestrator)
           ├── Config      — profile configuration
           ├── Beeper      — sound (Web Audio API)
           ├── Keyboard    — keyboard input mapping
           ├── IO          — I/O ports (i8255A PPI)
           ├── Memory      — paged memory (ROM/RAM/VRAM)
           ├── Rom         — ROM image loading
           ├── I8080       — Intel 8080 CPU emulation
           ├── Viewport    — canvas management
           ├── Screen      — video output to canvas
           ├── Tape        — file I/O (File API)
           ├── DnD         — drag-and-drop file loading
           └── Watcher     — traps (BLOAD/CLOAD interception)
```

## Technology Stack

- **Language**: JavaScript (ES modules with ES3/ES5 style function constructors + prototype)
- **UI**: HTML5, CSS, Canvas 2D
- **Sound**: Web Audio API
- **Build Tool**: Vite 8.0.0
- **Linting**: ESLint with Prettier
- **Package Manager**: npm
- **Platform**: Modern web browsers (Chrome, Firefox, Safari, Edge)

## Code Patterns & Conventions

### Module System
- Uses ES modules (`import`/`export`) with `.js` extensions
- Entry point: `src/main.js` imports `Emulator` from `./emulator.js`
- All dependencies are explicitly imported

### Constructor Pattern
- ES3/ES5 style: `function Constructor() { ... }` + `Constructor.prototype.method`
- Type checking: `if (!(config instanceof Config)) throw new Error(...)`
- Properties defined via `Object.defineProperty(this, 'prop', { ... })`

### Async Initialization
- Critical change from sync to async due to binary file loading
- Chain: `main.js` → `Emulator.initAsync()` → `Computer.initAsync()` → `Profile.initAsync()`
- ROM and dump data loaded via `fetch()` from `public/data/*.bin`

### Binary Data Handling
- ROM images and dumps extracted from inline JS arrays to `.bin` files
- Loaded asynchronously: `await fetch('/data/rom-1990.bin')`
- Manifest file: `public/data/dumps-manifest.json` lists available dumps

## File Formats

- `.lvt` / `.lvr` / `.lv0`-`.lv99` — PC-01 program files
- `.sav` — LVOV/DUMP/2.0/H+ format snapshots
- `.e3` — Emulator 3000 format snapshots
- `.bin` — Binary data files (ROMs, dumps)

## Important Gotchas

### Audio Context
Modern browsers require user interaction to start audio:
- AudioContext starts in suspended state
- First click/keydown resumes audio via `context.resume()`
- Implemented in `src/main.js` with event listeners

### Binary Data Loading
- ROM and dump loading is now asynchronous
- Initialization chain must handle promises correctly
- Errors in loading will prevent emulator from starting

### Browser Compatibility
- File API replaces deprecated Chrome File System API
- `evt.which` still used but deprecated (to be fixed in Phase 3)
- `webkitImageSmoothingEnabled` still used (to be fixed in Phase 3)

### Known Issues (from IMPROVEMENTS.md)
1. `screen.js:111` - global variable `result` without `var`/`let`/`const`
2. `notify.js:69` - `innerHTML` used (potential XSS)
3. `memory.js:263` - `io.EXTENDED_MODE_PORT` should be `io.ports[io.EXTENDED_MODE_PORT]`
4. `screen.js:221` - incorrect grayscale formula (uses `&&` instead of multiplication)

## Performance Considerations

- CPU emulation runs in main thread (consider Web Worker for Phase 3)
- Large binary files (~2MB dumps) loaded on demand
- Canvas rendering uses `requestAnimationFrame`
- Audio uses Web Audio API with buffer scheduling

# Emulator PC-01 Lviv — Оценка проекта и список улучшений

## Общая характеристика

Проект представляет собой эмулятор советского компьютера ПК-01 «Львов» (1980-е гг.), реализованный как Chrome Packaged App (manifest v2) на чистом JavaScript и HTML5. Ядро эмулятора — это процессор Intel 8080 (КР580ВМ80А), страничная память, I/O-порты (i8255A), видеовывод на `<canvas>`, звук через Web Audio API и клавиатура.

**Состояние проекта:** последний коммит — v1.1.0, проект стабилен, но не обновлялся, технологически устарел.

### 10. Неоптимальная конвертация в grayscale (`screen.js`)

```js
// screen.js:221 — используется && вместо побитового умножения
sum = ((p & 0x00FF0000) && 0x1D) + ((p & 0x0000FF00) && 0x96) + ((p & 0x0000FF) && 0x4C);
```

Оператор `&&` выполняет логическую проверку, a не побитовое умножение. Если любой канал ≠ 0, результат — константа (0x1D, 0x96 или 0x4C), что **некорректно**. Для полутонов нужно:
```js
sum = ((p >> 16) & 0xFF) * 0.114 + ((p >> 8) & 0xFF) * 0.587 + (p & 0xFF) * 0.299;
```

> [!NOTE]
> **Уточнение:** После тестирования выяснилось, что использование `&&` вместо умножения — это НЕ ошибка, а особенность эмуляции. Такая логика даёт более яркое изображение, похожее на реальный ч/б телевизор PC-01. Исправление на правильное умножение делает изображение слишком тёмным. Код оставлен как есть с поясняющим комментарием.

### 11. Оптимизации производительности рендеринга (`screen.js`)

> [!NOTE]
> **Реализовано:** Добавлены две ключевые оптимизации для повышения производительности рендеринга:

#### 11.1. Предвычисленный кэш grayscale-палитр
**Проблема:** Каждый пиксель (4 на байт) вычислял grayscale в реальном времени: `~~(p & 0x00ff0000 && GRAYSCALE_RED_WEIGHT) + ...`
**Решение:** Предвычисленный массив `static cache_grayscale = []` со значениями ARGB для всех 128 палитр.
**Выигрыш:** Устранено ~196,608 операций на кадр (12 операций/пиксель × 16,384 пикселя).

#### 11.2. Условный вызов `putImageData()`
**Проблема:** `putImageData()` вызывался каждый кадр, даже если изображение не изменилось.
**Решение:** Флаг `dirty` отслеживает изменения; `putImageData()` вызывается только при `dirty === true`.
**Выигрыш:** Устранены дорогостоящие вызовы Canvas API для статических экранов.

**Реализация:**
```js

static cache_grayscale = [];

// screen.js:123-133 (в init())
// Precompute grayscale values for this palette
const grayscale = new Uint32Array(4);
for (let i = 0; i < 4; i++) {
  const p = rgb[i];
  const sum =
    ~~(p & 0x00ff0000 && GRAYSCALE_RED_WEIGHT) +
    ~~(p & 0x0000ff00 && GRAYSCALE_GREEN_WEIGHT) +
    ~~(p & 0x0000ff && GRAYSCALE_BLUE_WEIGHT);
  grayscale[i] = 0xff000000 | (sum << 16) | (sum << 8) | sum;
}
Screen.cache_grayscale[palette] = grayscale;

// screen.js:270-273 (в draw())
if (dirty) {
  this.context.putImageData(this.image_data, 0, 0);
```

### 38. Dirty rectangle tracking для оптимизации рендеринга

**Проблема:** Каждый кадр перерисовываются все 65,536 пикселей (256×256), даже если изменился только 1 пиксель.

**Решение:** Отслеживать только измененные области (dirty rectangles) и обновлять через `putImageData()` с ограниченными координатами:
```javascript
// Вместо полного обновления:
this.context.putImageData(this.image_data, 0, 0, 0, 0, 256, 256);

// Обновляем только измененную область:
this.context.putImageData(
  this.image_data,
  dirtyX, dirtyY,           // координаты в ImageData
  dirtyX, dirtyY,           // координаты на canvas
  dirtyWidth, dirtyHeight   // размер области
);
```

**Алгоритм:**
1. Отслеживать минимальный bounding rectangle измененных пикселей
2. Объединять несколько изменений в один прямоугольник
3. Сбрасывать прямоугольник после отрисовки

**Особенности PC-01:**
- Разрешение: 256×256 пикселей
- Видеопамять: 4 пикселя на байт → 64 байта на строку
- Координатная система: нестандартная, требует аккуратной обработки

**Выигрыш:** Максимальный для текстовых редакторов, меню и статических экранов, где изменения локализованы.

### 39. Архитектурный рефакторинг рендеринга (Screen ↔ Viewport)

**Проблема:** Screen компонент смешивает логику эмуляции видео с операциями canvas.

**Решение:** Четкое разделение ответственности:
1. **Screen** → генератор данных:
   - Метод `draw()` возвращает `ImageData` или `null` (если ничего не изменилось)
   - Удален `this.context` - Screen не знает о canvas
   - Удален `this.screenshot_type` - Screen не делает скриншоты
   - Фокусируется только на эмуляции видео: преобразование VRAM в пиксели

2. **Viewport** → рендерер:
   - Добавлен метод `render(image_data)` для отрисовки ImageData на canvas
   - Добавлен метод `shoot(screenshot_type)` для создания скриншотов
   - Viewport управляет canvas context и настройками сглаживания
   - Viewport отвечает за все операции с canvas

3. **Profile** → координатор:
   - Вызывает `screen.draw()` для получения данных
   - Передает данные в `viewport.render()` для отрисовки
   - Использует `viewport.shoot()` вместо `screen.shoot()`

**Преимущества:**
- **Тестируемость**: Screen можно тестировать без canvas
- **Гибкость**: Можно легко менять рендереры (WebGL, другой canvas)
- **Чистота**: Каждый компонент делает одну вещь хорошо
- **Подготовка к оптимизациям**: Viewport может кэшировать, использовать Web Workers и т.д.

**Реализация:**
```javascript
// screen.js
draw() {
  // ... вычисление пикселей ...
  if (dirty) {
    this.dirty = false;
    return this.image_data;  // ← возвращаем данные, не рендерим
  }
  return null;
}

// viewport.js
render(image_data) {
  if (!image_data) return;
  const context = this.canvas.getContext('2d');
  context.putImageData(image_data, 0, 0);
}

shoot(screenshot_type = 'image/png') {
  return this.canvas.toDataURL(screenshot_type);
}

// profile.js
function animation_handler() {
  const image_data = screen.draw();
  if (image_data) {
    viewport.render(image_data);
  }
  timers.restart = window.setTimeout(main_loop, 0);
}

shoot() {
  // ... использует viewport.shoot(config.screen.screenshot_type)
}
```

**Проблема:** Каждый кадр перерисовываются все 65,536 пикселей (256×256), даже если изменился только 1 пиксель.
**Решение:** Отслеживать измененные области и обновлять только их через `putImageData(x, y, sx, sy, sw, sh)`.
**Выигрыш:** Максимальный для текстовых редакторов, меню и статических экранов.

#### 2. WebGL рендеринг
**Проблема:** Canvas 2D API медленный для частых обновлений.
**Решение:** Использовать WebGL для рендеринга через текстуры:
- Загружать `ImageData` в WebGL текстуру
- Рендерить через шейдер с поддержкой палитр
- Добавить фильтры (CRT-эффект, scanlines)
**Выигрыш:** 10-100x производительность, эффекты ретро-эстетики.

#### 3. Динамический aspect ratio
**Проблема:** Фиксированный aspect ratio 4:3 в коде.
**Решение:** Добавить UI переключатель и динамическое изменение:
- 1:1 (квадратные пиксели)
- 4:3 (традиционный CRT)
- 16:9 (широкоэкранный)
- Автоматический под размер окна
**Реализация:** Метод `Viewport.setAspectRatio(value)` с пересчетом размеров.

#### 4. Интерполяция масштабирования
**Проблема:** Билинейная интерполяция (`imageSmoothingEnabled`) размывает пиксельную графику.
**Решение:** Добавить выбор алгоритма масштабирования:
- Nearest-neighbor (пиксельная графика)
- Bilinear (сглаженная)
- CRT-фильтр (ретро-эффект)
**Реализация:** CSS `image-rendering` или WebGL шейдеры.

#### 5. Поддержка HiDPI/Retina дисплеев
**Проблема:** Canvas не оптимизирован для high-DPI экранов.
**Решение:** Автоматическое определение `devicePixelRatio`:
```javascript
const scale = window.devicePixelRatio || 1;
canvas.width = 256 * scale;
canvas.height = 256 * scale;
canvas.style.width = '256px';
canvas.style.height = '256px';
```

#### 6. Цветовые коррекции и фильтры
**Проблема:** Ограниченные возможности цветокоррекции.
**Решение:** Добавить фильтры через Canvas API или CSS:
- Яркость/контрастность
- Цветовая температура
- CRT-эффект (scanlines, bloom)
- Режим монохромного монитора

#### 7. Адаптивное масштабирование под размер окна
**Проблема:** Фиксированный масштаб 2x.
**Решение:** Автоматический подбор масштаба:
```javascript
function calculateOptimalScale(containerWidth, containerHeight) {
  const maxWidth = containerWidth / 256;
  const maxHeight = containerHeight / 256;
  return Math.max(1, Math.floor(Math.min(maxWidth, maxHeight)));
}
```

#### 8. Поддержка полноэкранного режима
**Проблема:** Нет полноэкранного режима.
**Решение:** Реализовать через Fullscreen API:
- Кнопка переключения полноэкранного режима
- Автоматическое масштабирование
- Выход по ESC

#### 9. Сохранение скриншотов с метаданными
**Проблема:** Базовые скриншоты без информации.
**Решение:** Добавить метаданные в скриншоты:
- Дата и время
- Название загруженной программы
- Текущие настройки эмулятора
- Форматы: PNG, JPEG, WebP

#### 10. Анимации и переходы
**Проблема:** Резкие изменения (палитры, цветовой режим).
**Решение:** Плавные переходы:
- Анимация смены палитры
- Плавное включение/выключение grayscale
- Эффекты загрузки/сохранения

#### 11. Статистика рендеринга
**Проблема:** Нет информации о производительности.
**Решение:** Добавить отладочную информацию:
- FPS счетчик
- Время рендеринга кадра
- Процент dirty пикселей
- Использование кэша

#### 12. Многопоточный рендеринг
**Проблема:** Рендеринг блокирует основной поток.
**Решение:** OffscreenCanvas + Worker:
- Вычисление `ImageData` в Worker
- Передача через `transferable objects`
- Рендеринг в основном потоке
